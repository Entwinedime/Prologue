## 一、战略总目标（以多配置模拟预测为主，解耦单卡/局部提速对照）

在干净基线上高效完成 **SGLang + Ascend 全配置矩阵的端到端模拟预测验证**，产出具有说服力的跨拓扑、跨模型与真实流量预测总表：

1. **主线优先出多配置模拟预测结果**：每个新拓扑/模型优先采用**完整拓扑短流来源**快速建库，并走盲测隔离留出（`holdout.py`）跑通**结构全匹配 + 固定图基线合格 + 自主闭环 TTFT/TPOT < 6% MAPE + 跨配置排序一致**，绝不被单卡分片建库或自定义调度局部配方阻塞主线；
2. **明确划清采集边界，斩断特例滋生**：局部微探针严格限定在**“可由明确输入复现”的弱状态算子**（张量 shape、拷贝 bytes、通信组/独立短物理通信片段、Attention/Layer/Embedding）；依赖队列历史、前缀树、在途状态的调度切口一律由**完整拓扑短流自然触发**或**通用原生 `replay`** 解决；
3. **独立量化单卡装配与局部补采收益**：单卡分片建库（配独立短物理通信探针片段）与按需局部补采作为**清晰独立的对照项**，单独量化“能补什么、节省多少卡时、剩余结构差异在哪”，不与主线多配置预测强耦合；
4. **事前预登记消除参考波动争议**：独立留出冻结前预先声明轻量参考固定重复次数与中位数聚合口径，仍严格执行 `< 6% MAPE` 门槛，杜绝事后挑拣与无谓重跑。

## 二、四道不可逾越的核心边界

### 边界 1：三里程碑强停机门控（M1 → M2 → M3，每段完必停）
- **M1（多卡 TP 与跨模型预测矩阵 + TP2 单卡装配独立对照）**：
  - **主线**：完整拓扑短流建库 → 独立盲测留出，覆盖 **Qwen3-8B TP2、TP4、TP8** 与 **Mistral-7B-v0.3 TP2**，交付跨 TP 吞吐/TTFT/TPOT 精度与排序一致性表；
  - **独立对照项（不阻塞主线）**：Qwen3-8B TP2 单卡分片 + 独立短物理通信探针片段装配对照，量化单卡建库卡时收益与剩余差异；
  - **强制停机验收**：交付 M1 证据表与源码 diff 后停机，等待 AGY/用户确认放行 M2。
- **M2（异构高级并行预测矩阵：PD + PP + MoE-EP）**：
  - 全部优先使用完整拓扑短流建库 → 独立盲测留出，覆盖 **PD 分离（Qwen3-8B Prefill TP1 / Decode TP2）**、**流水线并行（Mistral-7B PP3、TP2×PP3）** 与 **稀疏 MoE-EP（Qwen3-30B-A3B TP4×EP4）**；
  - 严禁为 PD/PP/EP 编写新的逆向调度局部构造脚本；若某子拓扑确受原生框架/硬件限制，按止损线留存原表证据并单列边界结论后继续其余拓扑；
  - **强制停机验收**：交付 M2 证据表与源码 diff 后停机，等待 AGY/用户确认放行 M3。
- **M3（Azure 2024 真实流量压测 + 8 域总验收与公开文档收口）**：
  - 基于本机已核验的官方 Azure 2024 会话 CSV（严格按不重叠行范围隔离 Dev/Holdout），完成 **32 → 128 → 256 请求** 高并发预测与留出验证；
  - 汇总已终审的 **S05 R6 单卡复杂调度（5/5，1.00%–3.96% MAPE）+ M1 + M2 + M3**，交付统一总表 `data/multi-config-prediction/holdout/accuracy-summary.json` 与跨配置排序总表；
  - 同步更新 `README.md` 与静态设计文档，全仓品质复核通过后停机交回 AGY 终审。

### 边界 2：采集反特例红线（按“能否由明确输入复现”严格划界）
- **允许局部微探针的范围**：张量 shape、拷贝 bytes、通信组/独立短物理通信片段、Attention/Layer/Embedding 等弱状态明确输入算子；
- **严禁新增特例剧本**：**严格禁止**为 TP、PD、PP、MoE-EP 或复杂调度新增逆向构造框架内部状态机的配方逻辑（如新的 `*_frontier`、`*_seeds`、手工拼装缓存/驱逐/微批/异步预约队列的脚本）；`src/python/prologue/integrations/frameworks/sglang/acquisition/recipes/scheduler.py` 原则上**冻结不再膨胀**（仅允许修明确通用 Bug，绝不扩写新机制剧本）；
- **核心引擎纯净红线**：`src/engine/core/` 保持 0 框架/平台字样、0 配置特判、严格零外推契约不变。

### 边界 3：隔离留出、事前预登记重复参考与代码品质红线
- **Dev / Holdout 物理隔离**：开发建库与归因写入 `data/multi-config-prediction/dev/`，独立留出写入 `data/multi-config-prediction/holdout/`（可只读复用基线已验收的 S05 R6 / S06 证据并保持完整来源隔离）。
- **盲测隔离与透明披露**：独立留出冻结源码、镜像、二进制、配方与初始库，在完整参考目录尚未创建前完成盲测预测（允许通过正式 `predict explore` 在零接触参考前提下触发受控局部补采），三路核验须 100% 通过来源隔离（`training == "separate"`），报告透明列出初始热覆盖、自动局部补采次数/卡秒与完整参考卡秒对照。一旦暴露代码 bug、结构失配或超 6% 精度缺陷，须退役进 Dev 修复并换新留出重抽。
- **参考波动事前预登记（严禁事后补测挑拣）**：冻结每个里程碑留出清单前，须**预先声明**各案例的轻量原生参考固定重复次数 `K`（例如短批/易波动案例固定 `K=3`，多卡稳定大负载固定 `K=2`）及聚合口径（每请求 TTFT/TPOT 取 `K` 次独立轻量录制的**中位数**作为参考真值，同时在报告中逐次列明单次 MAPE 以供审计），统一按严格 **`< 6% MAPE`** 判定；**严禁**看到某例落在 `6%–8%` 后再临时事后补测。
- **架构与代码品质零回退**：新增扩展须经 `common/components.py` 包贡献机制，严守四维隔离红线（`engine/core/` 0 框架/平台字样、`sglang/` 0 `ascend`/`torch.npu`、`abi/` 外 0 `sglang.srt.`、`ascend/reference/` 0 导入 `analysis/`、纯 `COPY` Dockerfile），保持 **> 550 NE 业务 Python 模块 = 0、函数体内 > 25 行无空行代码墙 = 0、AST 0 环 / 0 缺失、`ruff` 0 错、活动源码 0 `.pyc`、C++ Release 0 error / 0 warning**。
- **非目标**：不实现 CUDA/vLLM 实机代码，不引入多机跨节点网络调度，不修改 `docs/note.md`、`.personal/`、`.clang-format`、`third_party/`、`deprecated/` 及历史 `data/` 资产。

### 边界 4：有界轻量预算与防钻牛角尖硬止损
- **分里程碑预算上限（实账累计，失败重试不清零）**：
  - **M1**：`≤ 18,000 卡秒`；
  - **M2**：`≤ 25,000 卡秒`；
  - **M3**：`≤ 25,000 卡秒`；
  - 全窗口防挂死总上限：**`70,000 卡秒`**、宿主后处理 **`120,000 秒`**、存储 **`256 GiB`**（单次多卡/长流量运行仍给足合理超时如 900s–1,800s，避免误杀）。
- **单点防钻牛角尖硬止损线（必须严格执行）**：
  - 任何**单一配置、单一 Bug 或单一精度缺口**，若**连续尝试超过 2 轮不同根因修复，或单点累计投入超过 3,000 卡秒仍未收口**，**必须立即停机向 AGY/用户汇报根因、已试方案与代价选项**；
  - **严禁**为了 0.5% 边缘误差或单点探针噪声反复重跑 4–6 轮，**严禁**抠旧日志拼凑预算，**严禁**发现计划前提不划算时仍盲目硬凑。
