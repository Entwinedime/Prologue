## 里程碑 M1：多卡 TP 与跨模型模拟预测矩阵 + 单卡装配独立对照

### 为什么做
优先拿到最核心的多卡扩展性（TP2 → TP4 → TP8）与跨模型（Mistral-7B）端到端模拟预测精度和排序结果，同时用 1 份独立对照实验量化“单卡分片 + 短物理通信探针片段”的真实收益与边界，彻底解耦预测主线与单卡建库研发。

### 改动与验证步骤
1. **预登记重复参考支持（薄通用改动）**：
   - 核查 `example/coarse_graph/holdout.py`、`matrix.py` 与 `acceptance.py`，支持在冻结清单中**事前声明**每案例轻量参考重复次数 `K`（M1 统一预登记 `K=2`，短批可按需预登记 `K=3`），采集 `K` 份独立 `recording_id` 的轻量纯时延参考，按请求级中位数聚合 TTFT/TPOT 真值并同时输出单次 MAPE 供审计。
2. **主线：完整拓扑短流建库与盲测留出（Qwen3-8B TP2/TP4/TP8 + Mistral-7B TP2）**：
   - 每个配置用 1–2 组覆盖跨页、多成员与典型长度的**完整拓扑短流**（开发目录 `data/multi-config-prediction/dev/m1/`）建库并核对结构与固定图基线（可按来源隔离规则只读复用 S06 已验物理通信/宿主资产，或直接用完整短流配对宿主录制）；
   - 严禁为多卡 TP 新增任何逆向调度状态脚本；遇到明确输入超界点允许留出盲测走正式 `predict explore` 的弱状态探针（Attention / Copy / 物理通信片段）或短流通用补齐；
   - 冻结 M1 留出清单，抽样全新未见请求（如 8–16 请求），完成盲测预测 → 完整物理详细参考 + 预登记 `K` 次轻量参考 → 三路核验（结构 `full_structure_matched`、固定图实测基线合格、三路 `training == "separate"`、中位数 TTFT/TPOT `< 6% MAPE`）与**跨 TP2/TP4/TP8 吞吐及延迟排序一致性**。
3. **独立对照项（不阻塞主线）：Qwen3-8B TP2 单卡 + 独立短物理通信片段装配**：
   - 用单卡分片来源（复用或新采 TP2 单卡短流）+ 独立短物理通信探针提供的真实通信与提交片段，执行严格整图结构对照；
   - 单独记录：**总卡时 vs 完整双卡建库卡时、动作匹配率、剩余差异归因**，写入 `data/multi-config-prediction/dev/m1/single-device-assembly-report.json`。

### 交接与强停机条件
- **交付物**：`data/multi-config-prediction/holdout/m1/acceptance-summary.json`（含跨 TP 排序表）、`single-device-assembly-report.json`、M1 卡时/后处理账本、`git diff --stat` 与全仓静态品质自查（`ruff`、AST、NE/25L 代码墙、四维隔离）。
- **单点止损**：任一配置/问题超过 2 轮不同根因修复或单点消耗 > 3,000 卡秒立即停机汇报。
- **强制停机**：M1 汇总完成（或触发止损）后立即停机，交回 AGY 与用户审阅后再启动 M2。

## 里程碑 M2：异构高级并行模拟预测矩阵（PD + PP + MoE-EP）

### 为什么做
在干净基线上集中验证 Prologue 对 LLM serving 三大最难异构并行形态——**PD 分离、流水线并行（PP / TP×PP）与稀疏专家并行（MoE-EP）**——的端到端结构与性能预测能力。

### 改动与验证步骤
1. **统一采用完整拓扑短流建库（严禁手搓逆向局部调度配方）**：
   - 在 `data/multi-config-prediction/dev/m2/` 下，按顺序逐一验证：
     - **PD 分离**：Qwen3-8B `Prefill TP1 / Decode TP2`（验证独立双池、KV 与 metadata 单边搬运、队列交接与自主时延）；
     - **PP 流水线**：Mistral-7B-v0.3 `PP3` 与 `TP2×PP3`（验证微批交错、阶段间激活传递与末级返回环）；
     - **MoE-EP**：Qwen3-30B-A3B `TP4×EP4`（验证显式专家路由、变长通信与非均匀载荷）。
   - 仅当真实物理对照暴露**框架/平台通用 Bug 或缺失的公共协议边界**时才修改源码；严禁编写新的逆向状态机局部配方。
2. **M2 冻结盲测独立留出**：
   - 事前预登记各拓扑轻量参考重复次数 `K`（默认 `K=2`），一次性冻结抽取未见请求，完成盲测预测、双参考录制与三路核验（`< 6% MAPE` + 100% 来源隔离）；
   - 若某个异构拓扑在 2 轮定位内确证受原生框架或硬件物理限制，保留完整原生任务表证据并单列边界结论，继续完成其余拓扑，不卡停整个里程碑。

### 交接与强停机条件
- **交付物**：`data/multi-config-prediction/holdout/m2/acceptance-summary.json`、M2 卡时账本与源码 diff 审视。
- **单点止损**：单拓扑/单问题 > 2 轮修复或 > 3,000 卡秒立即停机汇报。
- **强制停机**：M2 完成后立即停机，等待 AGY 与用户确认放行 M3。

## 里程碑 M3：Azure 2024 真实流量压测 + 8 域总验收与公开文档收口

### 为什么做
用真实生产到达分布与 prompt/output 长度分布（官方 Azure 2024 会话 CSV）检验 Prologue 在高并发真实流量下的长程稳定性、高并发排队精度，并汇总全仓 8 域结果形成可发布证据包。

### 改动与验证步骤
1. **Azure 2024 连续窗口真实流量接入**：
   - 在 `example/coarse_graph/prepare_matrix.py` 扩展支持直接从本机官方 Azure 2024 CSV 按**互不重叠的连续行区间**构造 Dev 与 Holdout 负载（严格隔离行号区间并写入抽样凭证）。
2. **阶梯并发压测与留出（32 → 128 → 256 请求）**：
   - 先在典型并发配置（如 Qwen3-8B TP1 复杂调度与多卡 TP2/TP4）跑通 32 → 128 → 256 请求真实流量开发回归与固定图误差归因；若误差归因明确指向某类工作需新增线性/多轴性能模型族，按现有可注册性能模型机制最小化增量扩展（保持 C++ 严格零外推）；
   - 完成冻结盲测留出与预登记重复轻量参考验收（`< 6% MAPE` + 吞吐误差 + 来源隔离）。
3. **8 域统一总表与收官文档/品质交付**：
   - 汇总 **TP1 复杂调度（引用已终审 S05 R6 5/5 证据）+ M1 + M2 + M3** 生成 `data/multi-config-prediction/holdout/accuracy-summary.json` 及跨配置排序一致性汇总；
   - 同步更新 `README.md` 与静态设计文档，执行全仓品质红线自查并交付工作区 `src/` 与关键证据 SHA-256 清单，保持零提交停机交回 AGY 终审。
