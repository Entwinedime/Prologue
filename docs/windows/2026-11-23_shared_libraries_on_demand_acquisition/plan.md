# Prologue 整仓重建与共享资产按需采集

**开始日期**　2026-11-23。**状态**　实施中。开窗基线为开发分支 `296d722`。

**评审入口**　[实现细节与边界走读](review.md)

**目标**　用户给出一个模型、多份配置和多组请求，就能得到逐目标的预测与适用范围。新任务复用合格的模板、性能和规则资产，遇到缺口时按已知需求批量补采。预测、采集和验证各自保留清楚的输入、状态所有者和结果依据。正式代码、示例和项目镜像由新实现独立构建。

## 1. 交付范围

首批环境为官方 SGLang、Ascend、dummy 权重、给定输出长度及单机。用 Qwen3-8B 建立主线，按交接资格引入 Mistral、Llama 和已有原生证据的 MoE。交付单卡分片与完整拓扑两种采集来源，并逐项恢复已交付的 TP、PP、EP、PD 和调度机制。TP × PP、小池调度组合及持续流量各有独立目标；新模型与配置先确认原生可运行。跨机、NVIDIA 和远程资产服务留给后续窗口。

上一窗口止于 55/57 项。关窗前最近一次阶段交付为 `83dbfab`，后续代码和文档纳入关窗快照。第 14–16 轮结果与第 17 轮部分开发证据保留在本地。持续真实流量、256 请求压力和同版本最终验收均由本窗口重新界定并登记。S01 核对关窗快照的源码基线及可复用的原生记录，按实际证据登记已匹配、局部可比或缺证的范围。

## 2. 用户输入与执行路径

| 合同 | 要求 |
| --- | --- |
| 模型及配置集 | 一次任务一个模型、dtype 和权重加载方式。每份配置明确逻辑角色及并行拓扑、attention backend、KV 页大小与容量、最大活跃请求和启用的调度策略。运行时由框架适配器解析这些字段，必要资产按实际初始化的实现求取。 |
| 请求 workload 集 | 每组请求拥有稳定 ID、相对到达纳秒、输入与输出 token 数，同刻按输入顺序确定到达次序。共享前缀通过内容或前缀 ID 表达；启用所需的 EP 拓扑时提供相应路由。合成内容、路由注入和实测来源在产物中标明。 |
| 初态、采集与预算 | 初态明确请求队列、KV 驻留和预热后工作区状态。真实采集、轻量参考及预测采用同一预热和计时起点口径，分别记录 KV 和工作区状态。逻辑拓扑与可用物理卡分开输入，预算独立限制尝试、物理卡时、处理时间与保留量。 |
| 探索与复现 | `explore` 对配置和 workload 的组合逐项运行，从共享发布选择资产，额度允许时按缺口补采。 `predict` 接收明确发布记录，以零采集复现一个目标。中断恢复读取原任务、已发布资产与累计费用。 |
| 结果 | 每个目标给出流程状态、使用的发布及证据、缺口或输出。TTFT 为提交到首 token 发布，PD 使用 Prefill 提交和 Decode 发布。TPOT 为首末发布差除以输出数减一，单输出单列不适用。吞吐用统一窗口与实际输出数计算。 |

正式运行的顺序为选择发布 → 启动原生控制 → 绑定动作并展开模板 → 查询服务时长 → 推进虚拟资源和时间 → 返回完成与请求输出。纯预测在控制进程中执行原生决策代码，核心提供虚拟资源、时钟和消息交付。遇到缺口时，当前目标保存能复查的查询。探索工作流在收齐本轮已知需求后决定是否补采。新证据发布后，受影响目标从相同初态重新执行，原生控制重新决定批次和分支。

## 4. 模板、控制及性能怎样交接

1. **观察到共同事实。** 框架适配器标记统一流程中的原生边界、成员、参数与资源效果，设备适配器独立给出提交、开始、完成及计时资格。只保留影响执行、依赖、资源状态、外部输出或成本归属的事件。缺证和只知上下界的事件带着原始依据交接。
2. **生成分层模板。** 定义保存自身工作、端口和可共享的局部结构。父子调用边保存条件、参数映射和就绪依赖。调用实例绑定请求、张量、槽位、角色和本次状态。父图通过输入、输出及可观察资源效果连接子图。同一局部定义可由多个父调用引用，子图内部差异只在会改变该调用契约时影响父图。
3. **用原生控制驱动实例化。** 预测中的原生控制拥有逻辑决定与请求进度，核心拥有物理映射的模拟视图、槽位、页、缓存驻留和完成时间。动作从经过验证的共同状态视图取参。实例化完成后取得全部已知工作坐标，必要成本齐全时才提交该动作的资源效果与在途工作。已有动作的有效结果保留用于定位，缺口恢复建立新的控制会话从初态重跑。
4. **一次实现成本语义。** 查询使用工作的稳定身份、阶段、已绑定特征、物理布置与实测边界。不同模型族登记读哪些特征、适用域和返回单位。Python 产出可验证的拟合参数，正式预测、补采规划和固定图用同一个 C++ 求值入口。工作自身服务、宿主提交、设备执行、通信与依赖等待分开，适用域变化先核对来源资格。
5. **确定泛化边界。** workload 变化在已有结构和特征条件下绑定新请求。配置变化先判断影响的是参数、已知原生分支、角色映射还是新的实现。模型、框架后端、dtype 或拓扑变化可保留经证据确认的共同子定义；目标父调用、分片布局和成本域分别获得资格。缺数据、缺变换和原生不支持分别报告。

### 4.1 三类规则与发布

| 声明 | 决策所有者 | 内容和约束 |
| --- | --- | --- |
| 模板规则 | 核心结构的调用与选择机制 | 可见的阶段、角色、形状和边界条件，选择已注册展开操作并绑定实参。图体和端口定义留在模板库。 |
| 性能规则 | 性能层的模型绑定 | 工作类型、有效特征、测量合同及模型候选。训练数据和通过验证的模型域留在性能库。 |
| 采集规则 | 通用补采规划与具体适配器 | 缺口类别、可准备的原生状态、采样入口、可得到的证据和成本估计。适配器声明并兑现入口条件，工作流分配资源和额度。 |

规则作者提交类型、适用作用域、可见事实、已注册操作、正反例和原生依据。条件与结果必须在业务所有者处有唯一解释。不同结果同时满足时保留冲突，缺失事实可能改变答案时报告该事实。规则目录维护声明和判例，普通目标使用已发布规则。规则格式只维护当前合同，资产修订用于复现和追溯。

本地资产保存为模板、性能、规则三个逻辑集合。一次发布记录同时固定三者与环境资格，运行固定所选记录。发布只追加经原查询验收的资产，完成后原子替换当前发布指向。并发提交检查当前发布与目标是否仍需要补采。历史任务可通过原发布和对应构建复现。规则与资产引用关系支持圈出受影响的复验范围。

### 4.2 补采与结果

- **同一批已知需求。** 先记各目标首个阻塞调用，继续核对能独立处理的其他目标。对已经完整绑定的动作批量查成本。合并相同工作与测量条件的需求，保留各自的受影响目标。下一轮原生控制产生的新批次另作已知需求。
- **先复用可验证事实。** 依次考虑重读已有记录、局部独立算子、由原生接口准备真实状态的短任务、最短必要的服务运行。选择依据包括证据是否等价、是否能准备前置状态、累计卡时和启动开销。单卡可取得真实本地分片及其工作；跨卡通信由匹配拓扑、载荷和角色条件的物理证据提供。
- **原查询证明补对。** 结构缺口逐项核对调用、工作及边界，成本缺口核对实测口径、特征和训练外点，规则缺口按适用条件复查正反例。发布后重跑受影响目标；无新可辨别证据、额度耗尽、原生场景未触发或方法不可行时，记录实际停止位置及合格存量。
- **产物分开存放。** 共享资产默认位于 `data/libraries/`。每次运行在 `data/runs/<run_id>/` 下保留输入、简洁摘要、机器交接和结果。大图、原始记录及逐事件明细按取证需求生成，引用能追到所属会话和发布。保留量及峰值分别计入任务。

## 5. 三条评价路径与隔离

| 路径 | 固定的量 | 要核对的量 |
| --- | --- | --- |
| 实测条件验证结构 | 同一目标与初态，逐工作可核对的实测服务及必要外部就绪。真实目标图由比较端持有。 | 控制器自行产生的实际批次、动作、token 区间、角色、端口、资源效果及因果关系。实测条件缺项和区间约束单列。 |
| 真实图验证性能 | 原生真实图、批次、依赖、资源及已测外部交付。先回算同次实测，单独核对交付约束前的执行进度。 | 同一正式成本查询替换服务时长后的端点、请求误差及归因。按工作族恢复实测，报告误差传递与输入等待。 |
| 自主预测闭环 | 目标输入、初态及发布资产，独立轻量原生计时归评价端。 | 请求的 TTFT、TPOT、吞吐、流程终点及可解释的首处分歧。记录实际完成和可评分分母。 |

每个单案例有一个负责参考核验的入口，后续步骤共用它确认的事实。详细和轻量参考各自检查统一预热、时钟、边界及来源用途。固定图的实测基线符合已登记的测量容差后，再解释预测成本误差。构造负例检查合同，原生证据验证真实运行资格。

独立对照先封存包、模型及来源资格、规则与性能发布、二进制和镜像、目标、用途、额度、评价器和分母。纯预测与允许补采从同一发布起点分别运行。补采组只依据用户输入、已到达的缺口及独立训练取证，评价目标的原始图和轻量时延始终由评价端持有。若使用同一完整目标实测来补资产，该结果属于有实测辅助的诊断。旧例和修复看过的例子属于开发回归。

## 6. 执行阶段

五个里程碑保留明确交付边界。每阶段有一个可运行或可审阅的主要产物，覆盖对应入口、消费链和反例。阶段开始根据上阶段证据重排当前范围。阶段结束比较 Git 起点和实际改动，审查相关代码、文件层次、文档及数据，按职责用英文 `type(scope): summary` 提交并推送开发分支。阶段未达到预定工作量或验收条件时记录已完成项、原因、影响和还缺的证据。阶段内集中开发、静态核对后统一构建和运行代表案例。

## 7. 实验矩阵和交付口径

S01 登记实际模型及配置。每族用相同部署、初态及请求几何建立可比较的对照，再改变清楚的目标因素。机制未实际触发时保留计划分母和原因。S18 封存具体的独立请求和原生预算，流量选取保留时间、长度及同刻次序的关联。

### 首批可执行合同

M1 以 Qwen3-8B、BF16、dummy 权重、`ascend` 后端和单机 TP1 开始。基础配置用 16 token 页、4 个活跃槽位、4,096 token KV 池、256 token Prefill 上限。采用 eager 执行，关闭 overlap、分块和前缀缓存。S03 为同一批新的短请求各采一份详细参考和轻量参考。S04 的对照增加跨页及错峰，保留发生差异的资源分支。M2 的第二个密集模型使用已有目录中的 Mistral-7B-v0.3，Llama-3.1-8B-Instruct 进入后续交叉对照。Qwen1.5-MoE-A2.7B 与 Qwen3-30B-A3B 是现有 EP 配对候选，实际路由、精度和布局资格按各批原生配置确认。

- 一个任务固定模型、dtype 和加载方式，配置与 workload 有唯一 ID，形成显式组合。请求的 token 数为正整数，`arrival_ns` 为非负整数。按到达时间及输入次序交付请求，保留原始到达值。模型位置、逻辑拓扑和物理部署分别绑定。单卡来源每次仅可见一张卡，能否采到物理通信证据在目标模式之外单独判断。
- 详细和轻量参考使用同一预热请求、提交分组与原生排空条件。工作区保持预热后的原生容量，KV 经原生清理，队列与在途工作归零。稳态窗口记录初始化、预热、正式提交和末次发布的位置。窗口内新加载或新专用化单独标记，保留影响范围。预测输入持有明确初态和计划到达，原生参考另外记录实际提交及接收；结构旁路只使用有资格的就绪和工作时长。
- 主机时间使用同机 `CLOCK_MONOTONIC_RAW`。设备起止以平台计数器和校准采样映射到主机时钟，保留校准范围与缺测依据。结构比较的实测输入不带真实批成员和图。固定图保留实测外部交付，先核对该约束前的本地进度。自主预测使用单独的轻量发布记录评分。吞吐窗口取首次提交到最后一个目标 token 发布，各自按实际完成输出计数。

### 早期局部取证的判定

**PD 父调用。** Decode 原生传输队列完成后才把请求交给等待队列。`get_new_prebuilt_batch` 按可用槽位从中准入，再用真实请求、已分配页和原生池构造 `ScheduleBatch`。先在这条路径验证只观察父边界的可行性，保留准入集合、源页表区间、目标拼接区间、每个复制子调用、依赖和进度效果。覆盖同批两成员及一个待准入成员，后续消费和资源释放仍由原生调度处理。已有详细完整参考可用于对照。若局部入口必须人工制造传输完成、页表或完整等待队列，停止这条入口探索，保留原生服务上围绕父边界减观测的路径。[原生完成与批准备](../../../third_party/sglang/python/sglang/srt/disaggregation/decode.py#L1873) · [原生复制和进度更新](../../../third_party/sglang/python/sglang/srt/disaggregation/decode_schedule_batch_mixin.py#L25)

**Decode attention。** Serving 经 `ScheduleBatch`、`ForwardBatch` 和 `ModelRunner` 通到实际 attention backend。定点取证先使用原生 Prefill 建立真实 KV，在 Decode 核对实际 query 行、KV 长度、页表、dtype、头、kernel 及提交、完成和必要写入。优先考察同一个原生池内 `ScheduleBatch.prepare_for_extend` / `prepare_for_decode` 和 `ModelRunner.forward` 的窄路径。SGLang 自带 batch 工具证明这些调用可以连起来，但其关闭 overlap、使用简化的缓存对象，出样前仍须和 serving 核对真实设备任务及生命周期。出现状态所有权、布局、backend 分支、kernel 或服务切口不一致时，停止局部路径并以原生 serving 窗口定位差异。[原生 batch 入口](../../../third_party/sglang/python/sglang/benchmark/one_batch.py#L456) · [Ascend Decode 实现](../../../third_party/sglang/python/sglang/srt/hardware_backend/npu/attention/ascend_backend.py#L2406)

- 同一物理目标在完整和单卡两种来源上走三条路径时，计划两份原生参考和六项基本评价。允许补采、旧版开销基线、额外返修留出各自计数；同一真值的离线复算只增加处理用量。
- 模板覆盖以独立参考的适用调用为分母，分开报告按分支的正确展开、误命中、漏命中和受首缺口阻塞的范围。性能覆盖以实际应查的不同工作坐标为分母，分开报告实测查表、模型估计与请求可评分覆盖。按来源和配置披露 TTFT、TPOT，结论只适用于各自合格范围。
- 用同口径比较旧流程、冻结库、允许补采和热库。费用含原生会话、完整 Engine、工作量、物理卡时、启动、预热、取证、后处理、峰值及保留量。规则变更、人工介入和专用脚本也登记，独立参考取得成本单列。每次失败照实计账。
