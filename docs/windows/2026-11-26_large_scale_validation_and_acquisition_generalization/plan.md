## 三、Layer 1：单卡复杂调度 + 局部补采泛化与冷启提速（S03–S05）

### S03　同会话多切点合批与常驻 Worker 复用（局部采集提速）
- **为什么做**：历史两个 attention 长度已合批，92.78 卡秒仍为同点完整服务的 **75.5%**，其中 45.36 秒用于预热。其他规则的批次补采仍有独立进程重复初始化。先把冷启动收敛到目标切点实际需要的原生工作，再复用兼容切点的 worker。
- **代码落点与设计边界**：
  - 沿用 `session_key` 与 `NativeAttempt` 的兼容分组。S03 优先收缩设备切点的准备，批次结构与独立宿主计时的兼容分组在 S04 随调度配方一起处理；
  - `--local-attention` 在一次原生 `ModelRunner` 会话中准备多组成员和长度。复用原生批次元数据和页分配，向真实 KV 池写入前缀，按唯一标记从一次 SDK 导出分别读取各切点。`--local-copy` 沿用已有的多坐标测量；
  - **边界红线**：严禁引入跨任务驻留守护进程或破坏单任务原子隔离，合批严格限定在同一任务会话与同一预算账本内。
- **验收门禁**：
  - 在空闲单卡上对照同一模型、配置、批次几何和目标调用。保留原两点基线，再覆盖跨页的多点和并发批次。局部合批相对同点完整服务总卡时 **< 50%** 的范围须明确记录于 `data/large-scale-validation/dev/l1/speedup-benchmark.json`；
  - 跨切点独立读回资格校验 100% 通过，0 状态串扰；
  - 交接：L0 底座 → 低冷启合批局部采集引擎 → S04 与全部后续波次。

### S04　扩展复杂调度机制局部补采配方（Prefix Cache / Chunked Prefill / Mixed Batch）
- **为什么做**：当前 [scheduler.py](../../../src/python/prologue/integrations/frameworks/sglang/acquisition/recipes/scheduler.py) 写死了 `impl["cache"]["disabled"] and not any(impl["scheduling"].values())`，导致启用 Prefix Cache、Chunked Prefill 或 Mixed Batch 时无法通过局部规则自动补采，只能被迫退回完整服务；且历史记录显示复杂调度下“续块前宿主时序与调度期 CPU 成本”仍是误差主因。
- **代码落点与插件边界**：
  - 严格通过 `common/components.py` 包贡献机制，在 `src/python/prologue/integrations/frameworks/sglang/acquisition/recipes/` 与 `observation/probes/` 新增或扩展以下局部配方（核心分发器 0 改动）：
    1. **Prefix Cache 局部配方**：构造含共享前缀的冷写入 → 命中复用 → 小池容量驱逐（`evict_from_tree_cache`）三种最小局部边界状态，输出对应结构片段与命中/驱逐 CPU 与设备成本样本；
    2. **Chunked Prefill & Mixed Batch 局部配方**：解除 `LocalSchedulerBatch` 的非分块/非混批限制，扩展 `priming()` 支持按 `max_prefill_tokens` 构造中间 chunk 续块与 Prefill+Decode 混批边界，同时覆盖续块前宿主 CPU 调度切口（配合 `paired_host` 双遍独立计时）；
    3. **并发页边界与 `allocation_prefix` 补采**：覆盖单成员/多成员 `allocation_prefix` 与 `block_table_strided=0/1` 页边界模板缺口。
- **实施顺序**：先用现行单卡独立录制定位分块和混批的实际成员、提交进度和端口，再让局部 worker 通过原生选择与结果处理到达声明的准备边界。随后验证缓存写入、命中和驱逐所需的状态能从请求内容及原生资源事实重建。最后合并兼容的批次准备与宿主计时任务，保持各结构录制和独立 CPU 计时的取证边界。
- **验收门禁**：
  - 新增/扩展配方全部由包贡献自动发现，优先级与 `EvidenceGap` 自动回退链通过验证；
  - 在单卡上经官方 `library acquire` + `library publish --from-session` 实测覆盖 Prefix Cache（命中+驱逐）、Chunked Prefill、Mixed Batch 及其组合的局部结构与宿主/设备成本补采；
  - 交接：S03 提速引擎 → 复杂调度局部补采插件集 → S05 开发回归与留出验收。

### S05　L1 开发回归、固定图误差归因与 L1 冻结独立留出验收（1 卡）
- **为什么做**：把 `Qwen3-8B TP1` 下的复杂调度机制从“结构跑通”推向“冷库自动补采 → 热库零卡复用 → 冻结独立留出 < 6% MAPE”。
- **具体实验矩阵（`Qwen3-8B` BF16，1 卡）**：
  - **配置集合**：① 标准池 + Chunked Prefill；② 标准池 + Mixed Batch；③ 标准池 + Prefix Cache；④ 标准池 + 三机制全开（`cache + chunk + mixed`）；⑤ 小 KV 池 + 三机制全开（强制触发缓存驱逐与队列背压）；
  - **Dev 集**：单请求 + 4–16 请求错峰到达与共享前缀组合，从空库跑通 `predict explore --deployment` 自动局部补采 → 热库零卡复预测 → `verify {source, structure, fixed-graph}`，按固定图误差归因补齐续块前宿主时序、同步搬运与 Attention 成本盲区；
  - **Holdout 集**：冻结 L1 源码与发布库，用独立未见请求（8–32 请求持续到达、混合前缀命中/淘汰、跨页分块长度）在物理单卡采集独立详细参考与轻量参考，运行三路验证。
- **实施顺序**：
  1. 三机制全开，先用一个跨页长请求从空库通过正式入口触发自动补采。按首个缺项区分工作不具备可复现的原生输入、已采工作无法发布、发布模型未覆盖三种根因。
  2. 用 1、4、12 请求与五组配置作开发回归。分块、混批、前缀缓存三种独立结构域各用独立开发库并行补采，三机制全开与小池变体共用结构域并检验容量变化。分别保存候选发布、同一输入热库复跑及变换后的覆盖。采集补充只发生在开发集；局部来源核对其发布片段，结构及固定图参考来自另外的完整服务。
  3. 用实测条件先收集五组结构首个缺口，采用真实队列与前一批执行还原局部切点。固定图用同一个 C++ 求值器批量定位缺少定义或超出范围的成本坐标，按原生调用合并必要补采，然后逐组替换验证误差传播。最后以轻量原生录制比较自主 TTFT/TPOT，三路都检查训练来源隔离。
  4. 冻结通过开发回归的源码、镜像、二进制、配方和初始双库。预先声明五组请求族和 8、16、16、24、32 请求规模，再以清单 SHA-256 一次抽取独立案例。每例以冻结初始库启动正式 `predict explore`，用单独的发布目录承接局部补采。封存全部盲测结果后采集详细和轻量完整参考，三路评分共用各例封存的最终库。需用于维修的案例降为开发集。
  5. 首轮未通过时，保留原冻结记录并把用于定位的案例归入开发集。先沿原生观察、模板候选登记和局部配方核对五例共用的 Decode 分配续段，同时从五张真实图一次列出全部缺失成本坐标。按原生调用和可复用来源归并缺口，核对原有观察能回答的范围后再补采。三路开发回归收口后重新冻结，以新清单抽取未见负载，并取得独立的详细和轻量原生参考。
- **L1 硬验收门禁**：
  - 5 组配置独立留出结构全部 `full_structure_matched`（0 差异）；
  - 固定图实测基线全部通过，热库在换请求/换容量下实现 0 新增卡时复预测；
  - 独立留出自主闭环 **TTFT MAPE < 6% 且 TPOT MAPE < 6%**，所有 `training` 隔离核验通过；
  - 交接：L1 冻结报告与低冷启复杂调度补采体系 → Layer 2。

## 四、Layer 2：多卡 TP2 / TP4 / TP8 与跨模型物理通信闭环（S06–S08）

### S06　多卡 TP 局部补采泛化、物理通信分组补采与多卡宿主成本
- **为什么做**：原局部 Attention 配方只覆盖 TP1。多卡 TP 需要分别获得单 rank 本地计算、物理组通信和逐 rank 宿主开销，并把三种来源汇入同一工作成本合同。
- **代码落点与边界**：
  - `recipes/attention.py` 与 `observation/model_samples.py` 共同支持 TP2/TP4/TP8 代表 rank（含 rank ≥ 2）的单卡分片 Decode Attention 局部采样与 KV 读回；
  - `recipes/services.py`（`LocalPeerWork`）& `platforms/ascend/host/collectives.py`：强化多卡物理通信（AllReduce / AllGather / ReduceScatter）按参与者集合、归约操作与端点分组的自动补采、HCCL 通知寄存器收紧与同操作数跨配置复用；
  - 补齐多卡 TP 下各 rank 宿主调度/同步提交 CPU 成本的独立采样与拟合覆盖（禁止无依据直接把 TP1 宿主样本硬复制到 TP8）。
- **验收门禁**：
  - 单卡顺序分片成功采样 TP2/TP4/TP8 所需代表 rank 局部结构与本地设备样本；
  - 物理 2/4/8 卡通信样本按操作数分组拟合后，在 C++ `prologue cost-points` / `work-costs` 上完整覆盖目标多卡通信特征坐标；
  - 交接：L1 底座 → 多卡 TP 本地分片 + 物理通信补采体系 → S07。

## 七、阶段演进与 Bigger-Picture Overview 记录（由 Codex 每阶段动态追加）

### S01　按原始事实拆开三项历史问题

PD 差异分布为 Prefill 75 处和两个 Decode rank 各 375 处。来源编译当前已能保存子调用分配，旧发布缺这项事实。TP8 需要由原始录制重新生成含等式 guard 的图。CANN 相邻任务的原始边界从整数任务表读取，主机 RAW 和设备校准仍独立核验。三项分别落在库资产、投影边界和原生时钟事实的所有者处。先走离线链路，以免因资产陈旧重复占用真机。下一批按 S02-A 到 S02-D 推进。

### S02-A　旧发布的缺项由模板生产恢复

原始训练录制经现行生产链重建后，独立对照的动作内容和依赖均为 5,355/5,355，原 825 处端口差异清零。分配归属由模板边界表达，原生控制、结构比较与成本模型沿用现行实现。这次重建复用了两份训练录制和留存目标，新增卡时为零，其通过范围是结构对照。S02-B 改变计时事实后，S02-D 用同一份真实目标的重新投影再次核对 PD，再比对冻结 TP1 的基础行为。

### S02-C　TP8 的资格由原始录制重投影恢复

旧派生图缺少当前模型 padding 的两个等式 guard。用现行解释和整数端点重投影后，八个 rank 的结构与时钟核验均通过，八设备时钟共同满足 1,700,774 条因果约束。来源资格属于原始录制和派生图，补采规则与控制器无需改动。此项复用留存录制，新增卡时为零，阶段只证明该录制可用于独立参考。单卡分片并发模板的覆盖和独立预测精度继续由 L2 判断。

### S02-D　合入平台符号声明并保留同案门槛

固定 TP1 的轨迹、成本输出与基线一致，PD 在新的端点图上保持零差异。全仓审查定位到四个设备专属 ABI 符号依赖 SGLang 版本表里的默认平台。沿现有 `PlatformDomain` 传递平台声明，框架 ABI 在装配时要求声明齐全。验证以实装符号逐值一致和 CPU-only 控制入口的固定回归为判据。CANN 归档检索和现行真机定向录制都未取得带重叠的正式同案证据，L0 保留该门槛。

三卡 PD 作为一次有界的同案复现。单卡定向录制中没有相邻端点接触，原现象来自 PD 的 Prefill。用 S21 首个观察批的 12 个请求恢复原到达、提示和生成长度，Prefill TP1 与 Decode TP2 采用原容量配置。此批同时核验最终平台 ABI 装配。至多一次，单次保留上限 16 GiB，采集最多 420 秒或 1,260 卡秒。验收仍须在同一份录制中确认原生端点消除 1 ns 重叠并通过独立来源核验。

### S02-B　同案证据门槛触发熔断

原生任务表提供真实设备端点，解释器与独立参考分别读取。历史三对重叠的复算成立，现行 TP1 证明新路径接入正确，联合参考资格仍要求来自同一份命中重叠且已封存的录制。三卡定向运行在正式录制阶段超时，Prefill 写出记录，Decode 与联合 profiler 材料未封存。录制事实不足处保留原始状态，L0 的规则与门槛继续生效。交回 AGY 时保留固定 TP1、PD、TP8 和 ABI 已核验范围，后续冷启与精度工作沿原三路验证口径待启动。

### L0 裁决与 S03 交接

AGY 已按历史原表 2,893 万行中三处重叠复算，以及现行 TP1 8,795 项精确端点中 457 处旧渲染 `+1ns` 偏差放行 L0。此前三卡录制的超时证据按原样保留。S03 从已合批的两个长度开始重做完整服务对照，区分容器开销、初始化、目标路径预热、观测和 SDK 导出。批次切点的进程复用需要保留独立的结构与 CPU 计时证据。

原有分组已能合并相同定义的成本需求。主要可省开销在目标外的模型前向、对空前缀使用通用逐形状分配以及重复导出 profiler。SGLang 适配器用原生页池准备真实前缀，保留 `ModelRunner` 的 Decode 调用和元数据；Ascend 适配器按各切点的原生边界校验设备工作，再从同一份 SDK 导出读时间。原两几何复测为 53.3%，八几何单卡对照为 34.1%，两组均通过全部原查询。S04 以实际调度状态为输入，继续核对连续分块、混批、缓存与宿主工作。单卡设备切点结果的测量资格限于当前 Qwen3-8B TP1 域。
