## 一、战略总目标（聚焦 SGLang + Ascend，暂不引入 CUDA / vLLM）

在单一窗口内打通**“路线二（局部按需补采泛化 + 同会话合批提速）”**与**“路线一（跨拓扑、复杂调度与真实流量的开发回归、固定图误差归因与冻结独立留出 < 6% MAPE 验收）”**的正向飞轮：

1. **清零历史结构与资格债**：根治留存 PD 对照中的 825 处端口差异（11 次 `prefill/0 run_batch`）、修复长窗口 CANN 1ns 舍入重叠、解决 TP8 留存参考 `unverified` 资格缺口与单卡分片并发模板覆盖缺口；
2. **局部按需补采跨机制/跨拓扑泛化、冷启提速与端点扩包络**：基于上一窗口建成的零改动插拔体系（`common/components.py` + `recipes/` + `probes/` + 优先级自动回退链），将局部补采能力从“无缓存无分块的稠密 TP1”扩展至 **Prefix Cache / Chunked Prefill / Mixed Batch、多卡 TP2/TP4/TP8、PD 分离、PP 流水线与 MoE-EP**，通过同会话多切点合批复用常驻 worker 将局部采样冷启卡时相对同点完整服务从历史 **75.5% 压至 < 50%**，并在按需补采命中特征轴超界（`outside_sample_ranges`）时，利用同会话合批顺手补齐该轴在声明配置下的关键端点/极值锚点，避免单点“挤牙膏”式串行重启；
3. **8 域全维度开发回归与固定图误差归因**：系统性覆盖本机全部 3 款模型（`/models/Qwen3-8B`、`/root/models/markov-next/Mistral-7B-v0.3`、`/root/models/markov-next/Qwen3-30B-A3B`）、8 个配置域（TP1、TP1-Cache-Chunk-Mixed、TP2、TP8、PD TP1/TP2、PP3、TP2×PP3、TP4×EP4）以及真实流量/高并发压力（32 → 128 → 256 请求），用轻量典型工况开发回归与固定图误差归因定位并消除宿主、设备与物理通信误差源；
4. **严格隔离的独立留出总验收（TTFT / TPOT < 6% MAPE）**：在完全隔离的独立物理拓扑留出矩阵上，验证**冻结代码/配方/初始库 + 盲测按需局部补采闭环**达成**结构对照全匹配 + 固定图基线合格 + 来源 100% 隔离 + 自主预测闭环 TTFT 与 TPOT 各自 < 6% MAPE + 跨配置排序一致**的发布级证据包。

## 二、四道不可逾越的核心边界（防止大窗口失控）

### 边界 1：五层严格纵深边界（L0 → L4，逐层闭合，严禁跨层混改）
- **L0（底座校准与历史结构债清零）**：先清零 PD 825 端口差异、CANN 1ns 重叠与 TP8 参考资格，再进入新能力开发；
- **L1（单卡复杂调度 + 局部补采提速与调度配方扩展）**：先用 1 卡攻克冷启提速与 Chunked/Mixed/Prefix Cache，让后续 L2–L4 直接享受低卡时补采红利；
- **L2（多卡 TP2/TP4/TP8 与跨模型物理通信闭环）**：隔离攻克多卡 TP 单卡分片泛化、HCCL 物理通信分组与跨模型（Mistral-7B）验证；
- **L3（异构高级并行：PD + PP3/TP2×PP3 + MoE-EP）**：隔离攻克双池单边传输、流水线阶段交接与条件 EP 路由/变长通信；
- **L4（真实流量 Azure 2024 Trace + 高并发压力 + 模型族误差驱动演进 + 8 域总冻结留出矩阵）**：汇总全能力接受真实负载与大规模并发终极检验。
- **层间硬门控**：上一层开发回归与冻结留出核心门禁未达标前，严禁带着未收口的根因跳入下一层（确属原生框架/硬件物理限制的边缘子项须经 2 轮定位留证、单列边界结论后方可继续）。

### 边界 2：开发回归集（Dev）敏捷验证与独立留出集（Holdout）严格来源隔离（2026-11-27 经用户裁决修订）
- **敏捷开发回归（`dev/`）**：所有源码修复、局部配方开发、固定图误差归因、性能模型族演进与基础建库一律在 `data/large-scale-validation/dev/` 下完成；开发阶段聚焦覆盖核心机制、结构零差异、配方可用与典型工况 `< 6% MAPE`，**不再要求为赌中留出随机角点而在开发期穷举式预铺高维边界**；
- **独立留出冻结与严格隔离的按需局部补采（`holdout/`）**：
  - 独立留出验证全部写入 `data/large-scale-validation/holdout/`，必须使用**开发结束后冻结的源码、镜像、二进制、配方与初始基线双库**，并以冻结清单 SHA-256 为唯一 `--seed` 经 `prepare_matrix.py` 一次性抽出未见请求，在目标完整物理拓扑上采集独立详细参考与轻量参考；
  - 独立留出预测阶段**严禁修改任何代码、镜像或配方**，**严禁接触或读取独立完整服务参考录制（`native` / `latency`）**；
  - 预测优先复用冻结初始库热命中；若在盲测中遇到未见分支（`template_gap`）或超区间坐标（`outside_sample_ranges`），**允许通过正式 `predict explore` 在零接触参考的前提下，自动触发局部微切口按需补采并增量发布留出期新库以完成预测闭环**（同步利用同会话端点扩包络能力，遇到特征轴超界时在同一探针会话内顺手补齐该轴在当前声明配置下的关键端点/极值锚点，避免单点多次重启）；
  - 留出期局部补采产生的探针录制拥有全新独立 `recording_id`，所有最终结构对照、固定图验证与自主评分必须使用完整隔离校验——**三条验证路径的 `training` 字段须 100% 通过来源隔离核验（0 例 `reference_used_for_training` 或 `training_origin_unverified`，与完整服务参考零交集）**，并在结果报告中**强制透明披露初始热命中/覆盖率、留出自动局部补采次数与补采卡秒（对照完整服务参考卡秒）以及是否纯热通过**；
- **反泄漏铁律不变**：一旦独立留出暴露出**代码 bug、配方缺失/失败、结构失配（非 `full_structure_matched`）、固定图基线失败或自主预测超 6% MAPE**，该留出案例立即永久降级为开发集，修改代码或配方后必须换全新独立留出负载与新物理采集重新取证。

## 三、AGY 终审硬门禁与熔断规则

终审时 AGY 将独立复算并抽检全部产物，**任一门禁不达标即打回返工**：

1. **结构零差异与历史债清零**：TP1（基础 + 复杂调度）、TP2/TP4/TP8、PD（原 825 端口差异清零）、PP3/TP2×PP3、MoE-EP 的独立物理结构验证达到 `full_structure_matched`（若个别超边界条件触发原生框架/硬件物理限制，须留存完整原生任务表证据并单列限制，绝不靠改口径放过）。
2. **局部补采泛化、冷启提速与超界端点扩包络实证**：
   - 新增的 Prefix Cache / Chunked / Mixed、多卡 TP、PD、PP、MoE 局部补采配方全部经 `recipes/` + `probes/` 插件注册（核心分发器改动 = 0 行），并在 Dev/Holdout 中有真实按需局部补采（含超界同会话端点扩包络）与零卡热复用日志佐证；
   - 局部采样冷启卡时相对同点完整服务实测 **< 50%**（对比历史 75.5% 给出同口径对照账本）。
3. **8 域独立留出精度与效率总表**：交付 `data/large-scale-validation/holdout/accuracy-summary.json`，逐域逐案例列出结构状态、固定图基线误差、成本替换后固定图误差、自主闭环 **TTFT MAPE、TPOT MAPE**（硬目标均 **< 6%**）、吞吐误差、跨配置排序一致性，以及**初始热覆盖/是否纯热通过、留出隔离自动局部补采次数与卡秒消耗（对照完整服务参考卡秒）**，且全部来源隔离核验通过。
4. **代码品质、文档同步与零提交快照绑定**：交付 `data/large-scale-validation/source-manifest.json`（工作区 `src/` 逐文件 SHA-256）与 `evidence-manifest.json`（全部关键证据 SHA-256），确认全仓品质红线零回退、`README.md` 与静态设计文档同步更新、全流程零 `git commit`/`git push`。
5. **高阈值真阻断熔断（严禁轻易停机打断连贯推进）**：
   - **不要熔断的情形**：① 概率性偶发复现条件（如随机硬件调度未撞出 0ns 相邻接触对，只要逻辑修复已有原表/现行流水线双向实证即放行，留待后续大流量顺带验证）；② 单次命令因预设超时偏短未封存（放宽至合理超时如 900s–1,800s 重跑或调优参数）；③ 某单一非核心子案例确受原生上游/硬件限制（完整留证并在报告中单列边界结论后，**继续推进其余拓扑与层级，绝不因单个边缘子项卡停全窗口**）。
