# 用户输入与结果合同

一次任务是一个固定模型、非空配置集合和非空 request workload 集合。用户提供探索范围、采集部署及累计预算，系统选择代表来源并管理原生生命周期；用户不指定 base，不维护 KV、worker 或模板。

当前入口 `prologue plan <task.json>` 读取 `model`、`configurations` 和 `workloads`，输出按配置及 workload 组成的目标以及稳定排序后的请求。以下说明同时约束后续探索、采集和预测。模型、框架和配置的运行资格按实际证据声明。

## 模型、配置和部署

| 内容 | 含义 |
| --- | --- |
| 框架 | 由应用选择原生适配器，SGLang/Ascend 为接入主线 |
| model.path / dtype / load_format | 模型路径、显式 float16 或 bfloat16，以及当前使用的 dummy 加载方式 |
| configurations | 唯一 ID 的配置集合，声明 backend、页布局、并行、调度和容量 |
| workloads | 唯一 ID 的请求集合，可声明共享前缀及按 EP 拓扑给定的路由条件 |
| 采集模式 | 完整来源按原生拓扑分配设备。单卡来源的采集容器仅可见一张设备，适用范围取决于适配器能执行的真实分片。 |
| 物理部署 | 采集使用的物理设备与目标逻辑拓扑分开声明。独立物理通信样本包含预测使用的物理放置和原生通信实现。 |
| 采集额度 | 原生卡时、后处理、尝试数和存储分别限制，失败及恢复累计计费。 |
| 给定耗时 | 模拟工作时长为非负整数纳秒。自主预测和实测结构对照分别使用成本资产和实测条件。 |

控制使用原生代码，并通过共同资源和完成接口驱动展开。真实请求、KV 与 worker 在采集时归框架管理；预测时原生决定逻辑动作，核心维护资源和模拟时间。

同实例配置包含 TP、可选 PP/EP、max_running_requests、max_total_tokens、max_prefill_tokens、page_size 和 attention backend；可选择 chunked prefill、mixed 及一级 prefix cache。微批次上限与原生 PP lane 分别解释，不从总请求数直接决定实际 batch。

SGLang 同实例的 `prefill_chunk_tokens` 以 token 计，取 `page_size` 的非负整数倍，零或省略表示关闭。`mixed_batches` 默认关闭，开启时需要正的分块上限。一个混合批次内的 Prefill 和 Decode 成员各有自己的 KV 读取长度、新写入范围及输出责任。

PD 配置分别声明 Prefill/Decode 的拓扑、槽位和 KV 容量；两池模型、dtype、backend 和页布局一致，资源独立。chunk 由 Prefill 侧推进；两池的缓存分别服从原生支持范围和各自来源实现，不共享缓存状态或隐式沿用另一池的开关。不把同实例 serving 的来源直接当作 PD 来源。

SGLang/Ascend 的 PD 任务在配置顶层给出 `id`、`attention_backend`、`page_size` 和 `disaggregation`。`disaggregation.prefill` 与 `disaggregation.decode` 分别给出 `tp`、`max_running_requests`、`max_total_tokens` 和 `max_prefill_tokens`。这条接入路径接受稠密模型和 Prefill TP1，Decode 的逻辑分片来自目标 TP。原生预分配的附加槽位由适配器声明，与准入上限分别处理。

所有配置先满足原生框架与设备的真实约束。项目不 patch 上游强行运行不支持的模型/并行策略；无法运行、缺来源、缺变换、缺时间依据及尚未验证分别报告。

外部输入在边界检查一次：类型、整数范围、唯一 ID、正容量、合法请求长度及路由覆盖等必须成立。未知或未实现字段不静默忽略，不保留旧字段和控制分支兼容。

## 来源与配置变化

| 变化 | 处理原则 |
| --- | --- |
| 请求数量/长度、到达、并发和 KV 总容量 | 同域内根据模板参数、状态和有限规则变换、连接；不保证任意范围 |
| 模型、dtype、TP/PP/EP、backend、原生实现或依赖、page_size | 规划相应新来源，模型/原生配置自动解释的部分不要求用户手改模板 |
| chunk/mixed/cache 机制 | 建立相同机制的来源，参数变化按规则展开，组合须有实际资格 |
| 仅设备位置绑定 | 不改变本地结构时复用定义；真实链路/异构成本另需依据 |
| overlap/speculative/多级实际搬运等扩展 | 需要明确控制、状态与模板能力，不因原生包含代码就自动授予支持 |

不同来源域是工程支持边界，不是理论不可能声明。粗化允许隐藏内部 kernel 差异，但不能隐藏目标变换所需参数和外部作用。能够展开、具有独立结构证据和性能可预测分别说明。

镜像记录实际不可变身份。仅采集包或输入校验维护时，先核对原生代码、依赖、观察与资产合同是否改变，再决定可复用范围；不能仅凭标签相同复用，也不因镜像ID改变就一律重采。

单卡模式按目标拓扑启动必要的逻辑角色，轮流在同一物理设备执行本地分片，并在原生通信边界交接真实操作数。等价角色可以共享详细模板。逻辑参与者、详细观察的角色数和物理卡数分别记录。

跨卡服务按实际参与者、方向、实现和张量布局匹配独立物理样本。实例化得到的各端口元素数供成本模型求值，估值限于所选物理样本的实测范围。单卡本地暂存计入采集开销。缺少载荷规则、匹配样本或对端时序的工作按缺口报告。网络争用和采样范围外的耗时各需相应证据。

## 请求与内容条件

每请求包含唯一非空 id、非负 arrival_ns、正整数 prompt_tokens/output_tokens，时间为整数纳秒。长度和合计不溢出有符号 64 位范围，并满足模型及原生单请求限制。

请求无需按到达排序，同刻按声明顺序处理。长度和固定输出不提供原生 batch、真实完成时间或控制答案；Prefill 产生首 token，输出 N 个 token 对应 N−1 次 Decode，具体切块和组批交给原生。

workload 可用 prefixes/prefix_id 声明内容共享关系；前缀 ID 唯一、父关系无环、累计长度不超过 prompt。声明不直接给命中结果，实际复用取决于驻留、就绪、页及实现条件。未声明共享的请求部分和生成后缀为私有内容。

`prefixes` 的元素包含 `id`、本段的 `tokens`、可选的父 ID `parent`。请求的 `prefix_id` 指向一条从根到该段的路径。当前这套合成内容由单阶段实例在采集与预测中共同消费。

采集和原生控制共用确定的合成内容，分歧处实际 token 不同，不用长度相同虚构命中。需要的词表分支超过模型词表时明确报错；合成输入和注入的固定输出不代表真实权重自然生成。

每配置×workload 从统一预热后的已声明逻辑初态开始。加载、编译、预热不属于目标服务窗口，但计入采集费用；后续窗口内真实分配、等待和搬运必须承接。workspace 热状态与逻辑 KV 冷状态分别记录。

## 调度、缓存和路由

chunk 上限与 Prefill token 预算分别声明，非分块软预算的原生语义不改变。中间 chunk 推进驻留而不提前输出。mixed 决定能否同批执行 Prefill/Decode；Decode 准入/预算优先级按原生模式解释，不增加理想化自写策略。

布尔开关 `prefix_cache` 默认关闭。启用时使用单阶段稠密模型的原生 LRU Radix 缓存，设备 KV 池由活动请求和缓存共享。请求结束释放槽位与引用，缓存整页继续驻留直到原生选择驱逐。资源状态分别记录物理空闲容量、可驱逐容量和引用保护容量。

配置的可选整数 `ep` 声明专家组宽，默认值为 1。当前 SGLang Ascend DeepEP Normal 的组宽大于 1 时，原生实现要求 EP 与 TP 等宽。workload 的 `expert_routes` 以该宽度的十进制字符串为键，例如 `"1"` 和 `"2"`。适配器从加载后的原生专家组核对部署，明确按当前拓扑选表。

`assignments` 的每项使用 `request`、`layers`、`tokens` 和 `experts`，两个区间均为左闭右开。每个计算位置有一组互异的全局专家 ID，数量符合原生 top-k。加载到路由专家的模型均须提供适用表，包含 EP1。稠密模型使用普通请求字段。

`padding` 使用 `layers`、`tokens` 和 `experts` 声明补齐尾部可能用到的专家条件。适配器根据实际批次和原生对齐获得补齐量及各 rank 的输入，补齐条件覆盖不足时报告缺口。当前使用一条显式条件路径，合成权重运行和预测消费同一张表。

padding表声明连续位置的路由覆盖，实际补齐量是本次模型输入行数与逻辑token数之差。当前无DP/CP的执行布局按attention TP对齐，EP组大小不充当补齐上界；同一表可覆盖多个TP布局，未使用的位置不产生工作或缓存内容。每次使用必须同时满足实际TP对齐上界和已声明覆盖，不足就拒绝，不复制最后一条路由补齐。

原生和预测消费相同逻辑路由与 padding 条件，后端重排/复制/截断分别有实现依据。条件预测不声称从请求长度得到真实文本路由，dummy 权重观察不代表自然路由。

MoE 前缀共享同时核对 token 与全模型实际专家层的逐位置有序专家条件；区间覆盖普通层时，该层不参与缓存身份。PP 各 stage 使用同一份全模型专家层集合，不能仅按本地层判定共享。首次分歧后不继续共享，padding 不进入请求内容键。PD 交接和重新组批按请求逻辑位置解释，不使用来源 batch 序号。

## 时间依据与结果资格

自主预测固定一个任务目标及对应发布资产。请求到达来自 workload，服务时间来自资产，事件时刻由执行器依照资源和依赖推进。缺模型或超出实测样本范围时交接实际工作坐标。

结构阶段可提供粗图工作的给定服务时间，或显式使用固定真实案例的实测服务/事件条件进行验证；缺少依据不默认补零，零时长同步仍保留其依赖。原生控制消费核心虚拟时钟与事件，不以宿主进程的实际运行时间决定模拟结果。

局部构图验证可给定真实动作、批次和调用参数，由核心独立生成图。验证原生控制时，动作、组批及资源操作由实现产生，验证报告列出被旁路的输入及其影响。真实目标图在结构验证中用于比较，在固定图性能验证中作为已知输入，预测的服务时长和重算的时序另行评分。自主预测仍只接收配置、请求、模板与独立成本。独立目标隔离于模板生产和成本拟合，验证输入通过独立文件交接，workload 字段维持业务语义。

实测时刻、可见边界区间及必要同刻顺序按其真实依据使用；区间约束采用满足依赖的最早可行时刻，报告仍区分确定时刻与区间内的一种执行。工作按请求、阶段、token 范围、rank 及必要因果位置对应；首个无法对应位置明确报告，不按第几个轮询、批次或节点硬配。

结果分别说明流程是否完成、参考证据是否合格、实际对照范围和结论。结构验证报告真实时间条件及对比覆盖，固定图性能验证报告实测基线、成本覆盖和误差，自主预测报告独立原生评分。已匹配、确认差异、证据不足、原生限制、依赖阻断和工具错误分别记录。

粗图对照核对工作、参数、数据/资源依赖、通信及状态和完成边界；不要求内部 task 名称/数量相同。来源或真实目标缺少必要外部作用时仍报告对应范围不足。

请求输出表示 scheduler 向下游交出 token 的可见时刻，不包括 detokenizer、HTTP 和客户端接收。内部状态提交与用户输出分开，CPU 返回与设备完成分开。给定耗时/旁路均不构成性能模型或精度结论。

## 产物、恢复与隔离

每次配置集任务在 `data/runs/` 下拥有自己的运行目录，容纳可复现输入、任务状态、简洁摘要和可选明细。模板、成本和规则对象由本地共享发布记录一同固定。逐目标结果给出使用的发布、可比较的指标和实际用量。

原始 trace 只按构图/取证消费者生成和保留，已消费中间件及时释放。默认与明细使用同一次执行及相同业务结果，不能另跑一次模拟或只压缩 JSON 排版充当精简。

新任务读取明确输入和合格的发布资产。复用按模型配置、运行程序、镜像及部署身份核对。每个目标分别检查模板条件和成本特征范围。模板可用且缺少相应耗时的目标沿用该模板，先查询已有训练样本，再为仍缺的工作安排适用的性能采样。正式结果列出每个目标实际使用的资产，以及任务新增的尝试、原生计费时间和后处理时间。

同一任务只允许一个状态写者，镜像与原生身份记录实际值。原生阶段、角色事实闭合、模板发布和任务退出分别交接；离线处理失败优先复用本次完整事实，不反复启动原生。

恢复保持模型、配置、请求、生产依据及累计费用。输入或规则改变时明确建立相应新资产与评价基线，不自动兼容旧格式；时间依据改变从合法初态重算，不续用旧预测。

失败、超时、中断和预算停止保留真实原因，不发布成功资产。临时与保留量分别核对，只清理本任务拥有的资源；结构资格、流程退出和精度不得相互代替。
