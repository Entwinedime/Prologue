# 用户输入与结果合同

Prologue 的一次任务由**一个固定模型**、**非空配置集合**与**非空请求 workload 集合**组成。用户通过固定双库发布开展预测探索；允许补库或主动取证时，另行声明物理部署与累计预算。模型、框架、并行策略和配置的支持资格均以实际证据为准，不因配置字段合法而自动授予支持。

## 一、公开任务入口与核心输入合同

通过 `python3 -m prologue` 或安装后的 `prologue-cli` 调用下表各操作。`--libraries` 在预测时传固定发布目录。

| 公开操作 | 作用与关键输入 |
| --- | --- |
| `predict explore` | 用 `--input` 中的一个模型、多个配置和多个负载生成目标。传入固定发布、`--binary` 和 `--timeout`。启用补库时传可写存储、`--deployment` 与累计额度。 |
| `predict run` | 用一个目标、固定发布与二进制生成预测。输入可指定 `given_work_ns`，也可用 `--execution-inputs` 传入独立实测条件。 |
| `library acquire` | 用原始 `--query`、物理部署、输出位置、单次限时和累计预算采集局部证据。 |
| `library publish` | `--from-session` 配合原查询、二进制与限时发布到长期存储。`--from-collection` 从已编译的训练集合导入，可传独立的 `--costs`。两种来源均以 `--libraries` 指定目的地。 |
| `library inspect` | 接受固定发布目录或长期存储，在标准输出显示所选发布的模板、成本与来源摘要。 |
| `capture run/project` | 以物理部署和预算获取原生记录，再从指定来源投影模板或真实粗图。 |
| `cost extract/fit/acquire` | 按样本来源提取实测，拟合发布资产或根据真实缺项补采。 |
| `verify source/inputs/local-graphs/structure/fixed-graph/autonomous` | 分别核对原始证据、实测条件、局部展开及三条验证路径。每项显式传入本次的输入和输出位置。 |

### 公共输入字段合同

| 字段 / 参数 | 约束与语义 |
| --- | --- |
| `framework` | 原生框架及对应适配器，当前接入主线为 `SGLang / Ascend` |
| `model.path` / `model.dtype` | 模型路径与显式 dtype（`float16`、`bfloat16` 或 `float32`）；单次任务固定唯一模型与来源身份 |
| `configurations` | 唯一 ID 的配置集合，声明 attention backend、KV 页布局、并行拓扑、调度开关与资源容量 |
| `workloads` | 唯一 ID 的请求集合，支持可选共享前缀声明与按 EP 拓扑绑定的专家路由条件 |
| `deployment.acquisition_mode` | 建库与按需补库均支持 `full`（默认，按目标原生拓扑分配物理卡）或 `single_device`（恰好挂载一张物理卡，轮流运行目标分片） |
| `deployment.physical_devices` | 互异非负物理设备编号；Ascend 要求升序声明，容器内按序映射为逻辑设备 `0, 1, ...`；与目标逻辑拓扑解耦 |
| `--libraries` | 只读预测传固定发布目录（含 `release.json`）；自动补库或发布传可写长期库根目录，启动时锁定当前发布 |
| `--transport-samples` | 成本准备时显式指定物理通信样本（含实际物理放置与通信实现）；单卡用户可导入其他机器导出的合格样本 |
| 采集累计额度 | 通过命令行限制原生卡时/用时、后处理用时、尝试次数与存储字节上限；**失败、换请求与中断恢复均不清零** |
| `given_work_ns` | 单目标给定耗时模式的统一工作时长（非负整数纳秒）；仅用于开发验证与测速，不替代性能模型 |

### 配置边界与严格入口校验

- **同实例配置**：包含 `TP`、可选 `PP`/`EP`、`max_running_requests`、`max_total_tokens`、`max_prefill_tokens`、`page_size`、`attention backend`，以及可选的 `chunked prefill`、`mixed` 与一级 `prefix cache`。微批次上限与原生 PP lane 分别解释，不从总请求数直接推定实际 batch。
- **PD 分离配置**：分别声明 Prefill 与 Decode 两个实例的拓扑、槽位和 KV 容量；两侧模型、dtype、backend 与 `page_size` 必须一致，资源池完全独立。chunk 由 Prefill 侧推进；两池缓存各自遵循原生支持范围与自身来源，不共享缓存状态或隐式继承对端开关。同实例 serving 来源不得充当 PD 来源。
- **不强行修补上游**：配置须先满足原生框架与设备约束，项目不 patch 上游强行运行不支持的模型或并行策略；无法运行、缺来源、缺变换、缺时间依据与尚未验证五类状态分别报告。
- **边界单次严格校验**：类型、整数范围、唯一 ID、正容量、合法请求长度与路由覆盖在入口校验一次。未知字段或未实现能力立即拒绝，不静默忽略，不保留旧字段别名或历史格式兼容分支。

## 二、来源域、配置变化与采集部署

| 变更维度 | 处理原则与资格边界 |
| --- | --- |
| 请求数、长度、到达时刻、并发度、KV 总容量 | 同来源域内依据模板参数、资源状态与有限变换规则展开连接；不保证超出实测或变换边界的任意范围 |
| 模型、dtype、TP/PP/EP、backend、原生实现/依赖、`page_size` | 规划新来源域；模型与原生配置可自动解释的部分不要求用户手改模板 |
| chunk / mixed / prefix cache 机制 | 需匹配相同机制的来源域，参数变化按规则展开，组合须有独立验证资格 |
| 仅改变物理设备位置绑定 | 本地结构不变时复用模板定义；真实链路时延与异构成本另需对应物理依据 |
| overlap / speculative / 多级 KV 卸载搬运等扩展 | 须具备明确的控制、状态与模板合同，不因上游代码包含实现即自动授予支持 |

- **来源域边界说明**：不同来源域代表工程验证边界，并非理论不可行声明。粗化可隐藏内部 kernel 差异，但不得隐藏目标变换所需参数与外部作用。能够展开、具有独立结构证据与性能可预测三项资格分别报告。
- **镜像不可变身份**：镜像以实际不可变 ID 记录。仅维护采集包或输入校验时，核对原生代码、依赖、观察与资产合同是否变化以决定复用范围；不能仅凭标签相同盲目复用，也不因镜像 ID 变化而无差别重采。
- **双模式共用双库与通信样本**：`single_device` 与 `full` 共用模板库、性能库和预测入口。单卡模式按目标拓扑启动必要逻辑角色，在同一张卡上轮流执行本地分片并交换操作数，本地暂存计入采集开销；完整模式让各参与者在对应物理卡共同运行。等价角色可共享结构定义，资产条目保留用途、模式、物理放置、参与及详采角色。跨卡通信按实际参与者、方向、实现与张量布局匹配独立物理样本，估值严格限于样本实测范围；缺少载荷规则、匹配样本或对端时序时报告缺口，网络争用与域外耗时另需证据。

## 三、请求 Workload、内容条件与初态

- **请求基本字段**：每条请求须含唯一非空 `id`、非负整数 `arrival_ns`、正整数 `prompt_tokens` 与 `output_tokens`（单位为纳秒或 token），长度与累计值不溢出有符号 64 位整数且满足模型和原生单请求上限。
- **到达顺序与固定输出**：请求无需预排序，同刻按声明顺序处理。长度与固定输出不向预测器提供原生 batch、真实完成时间或控制答案；Prefill 产生首 token，输出 $N$ 个 token 对应 $N-1$ 次 Decode，切块与组批全权交由原生控制代码。
- **共享前缀声明**：支持通过 `prefixes` / `prefix_id` 声明内容共享关系；前缀 ID 唯一、父关系无环、累计长度不超过 prompt。声明仅表达内容共享，实际缓存命中取决于驻留、就绪、页对齐与原生实现；未声明共享的部分与生成后缀视为私有内容。
- **确定性合成内容**：采集与无设备控制共用同一确定性合成 token 生成逻辑，分歧点保证实际 token 不同，不以长度相等虚构命中；词表分支超出模型词表规模时明确报错。合成输入与注入固定输出不代表真实权重自然生成。
- **统一预热初态**：每个配置 × workload 均从统一预热后的已声明逻辑初态启动。模型加载、编译与预热不计入目标服务窗口，但计入采集费用；服务窗口内的真实分配、等待与搬运必须完整承接。工作区热状态与逻辑 KV 冷状态分别记录。

## 四、调度、缓存与条件 EP 路由

### 1. 调度与一级前缀缓存

- chunk 上限与 Prefill token 预算分开声明，不改变原生非分块软预算语义；中间 chunk 推进驻留而不提前输出。
- `mixed` 决定是否允许同批执行 Prefill 与 Decode；Decode 准入与预算优先级沿用原生模式，不叠加自写启发式策略。
- 首期 `prefix cache` 为设备 KV 池内一级缓存，与活动请求共享真实物理容量。请求结束释放槽位与引用后缓存页可继续驻留；仅核对终态空闲页不足以证明引用计数、淘汰与背压正确。

### 2. 条件 EP 路由与 TP 对齐 Padding

- **拓扑绑定**：配置声明 `ep.id` 与 `size`，workload 的 `ep_routes` 按拓扑 ID 提供条件，不隐式跨拓扑套用；专家到 rank 的映射由框架适配器决定。
- **路由赋值（`assignments`）**：按请求、层/token 左闭右开区间及全局专家 ID 描述；专家互异、数量匹配各层 top-k 且完整覆盖全部被计算逻辑位置。MoE 的 EP1 同样需要路由条件；dense 模型拒绝接收专家路由。
- **补齐表（`padding`）**：按拓扑声明连续尾部补齐位置的路由覆盖，实际补齐量为本次模型输入行数与逻辑 token 数之差。无 DP/CP 布局下按 attention TP 宽度对齐（EP 组大小不充当补齐上界）。同一表可服务多种 TP 布局，未使用位置不产生工作或缓存内容；消费时须同时满足实际 TP 对齐上界与已声明覆盖，不足即拒绝，严禁复制最后一条路由或补零默认专家。当前统一不自动从真实权重推导补齐元数据，不混用自动与手工模式。
- **MoE 前缀共享**：同时核对 token 与全模型所有实际专家层的逐位置有序专家条件（普通层不参与路由键；PP 各 stage 共用同一份全模型专家层集合）；首次分歧后不再共享，padding 不进入请求内容键。PD 交接与重新组批按请求逻辑位置解释，不依赖来源 batch 序号。条件路由与 dummy 权重观测不代表真实文本自然路由。

## 五、时间依据、指标口径与结果资格

### 1. 三种时间依据与独立参考原则

- **自主成本预测**：单目标输入含 `model`、`instances` 与 `workload`，由 `--libraries` 提供配对发布的模板与成本资产；缺模型或超出特征实测范围时发布首个成本缺口。
- **给定耗时 / 受控实测旁路**：结构开发可传入 `given_work_ns`，结构验证可显式传入经核对的实测时间条件（`--execution-inputs`）；缺少依据不默认补零，零时长同步保留依赖。给定耗时与实测旁路均不构成性能模型或精度结论。
- **完整物理拓扑独立参考**：三条独立验证路径的真值均来自目标完整物理拓扑的独立原生运行（单 worker 为单卡，多 worker 为实际物理放置联合运行），与模板建库和成本拟合严格隔离。单卡与完整来源的预测可共用同一留出目标对应的详细或轻量参考；仅具单卡分片记录且缺少多卡参考的目标标记为缺少完整拓扑真值。

### 2. 指标定义与结论分类

- **输出边界**：请求输出定义在调度器向下游交出 token 的可见时刻，不含 detokenizer、HTTP 与客户端接收；内部状态提交与用户输出分开，CPU 返回与设备完成分开。
- **核心指标**：TTFT 从请求提交（PD 取 Prefill 侧）起至首 token 发布结束；TPOT 按首末 token 发布差除以 $\text{output\_tokens} - 1$ 计算，单输出 token 标明不适用；吞吐按统一观察窗口与实际输出 token 数计算。
- **确定时刻与可行区间**：实测边界若为区间约束，执行器选取满足因果的最早可行时刻，报告明确区分确定时刻与区间内可行执行。工作按请求、阶段、token 范围、rank 与因果位置对应，不按轮询次序、批次号或节点号硬配。
- **六类独立结论状态**：每份结果分别说明流程是否完成、参考证据是否合格、对照覆盖范围与结论，明确区分 `已匹配`、`确认差异`、`证据不足`、`原生限制`、`依赖阻断` 与 `工具错误`；结构资格、流程退出与性能精度不得互相替代。

## 六、产物布局、双库发布与恢复隔离

### 1. 配置集任务目录布局

每次 `explore` 任务拥有独立的 UTC 时间根目录（默认 `data/<UTC>_exploration/`）：

| 目录 / 文件 | 职责与内容 |
| --- | --- |
| `inputs/` | 冻结的任务输入、双库发布身份、容器镜像摘要及编译程序快照 |
| `targets/<序号>/` | 各配置 × workload 组合的输入、预测结果、请求指标或首个模板/成本缺口；开启 `--details` 时保存展开轨迹 |
| `result.json` | 机器可读的逐组合资格、同 workload 指标排序、所用双库发布及累计用量 |
| `summary.md` | 面向人工阅读的简洁配置对比摘要 |

### 2. 发布、原子性与恢复规则

- **双库独立发布**：长期模板库、性能库与训练样本由独立发布目录持有，通过 `release.json` 固定双库入口与原生来源身份；只读预测在任务全程保持发布固定，移开旧任务目录后仍可独立复现。补库模式在发布新证据后仅从初态重算受影响的 worker/成本域目标，未受影响目标保留既有结果。
- **精简与明细同源**：原始 trace 仅按实际消费者生成，消费后及时释放。默认精简输出与 `--details` / `--execution-trace` 明细必须来自同一次执行，严禁重跑二次模拟或仅压缩 JSON 排版冒充精简。
- **单一写者与原子发布**：同一任务目录仅允许一个状态写者，通过临时文件原子落盘，禁止输入输出互相覆盖；失败、超时、中断或预算耗尽须保留真实原因，严禁发布空成功文件。
- **幂等恢复与格式边界**：中断恢复保持原模型、配置、请求、生产依据与累计费用；离线处理失败优先复用已闭合的原生事实，不重复启动原生 Engine。输入、规则或时间依据变更须建立新资产并从合法初态重算，不静默升级或兼容旧格式。
