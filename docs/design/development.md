# 构建环境与入口

C++23 核心用 Ubuntu 24.04、GCC 13、CMake、Ninja 构建。建模镜像 `prologue-modeling:ubuntu24.04` 提供工具和依赖，应用镜像 `prologue-app:ubuntu24.04` 安装当前 CMake 产物和 Python 包。构建过程只读本次源码，应用镜像从安装目录启动。Python 保持 3.10 语法基线。

当前公开入口 `prologue plan <task.json>` 在 CPU 容器中读取一份任务。Python 装配模型与配置，C++ 校验请求并生成稳定到达顺序，应用输出配置与 workload 的组合。模型位置在此阶段是部署输入。任务计划成功表示输入合格，原生运行、模板、成本和精度分别取证。

共同镜像 `prologue-sglang-runtime:ubuntu22.04` 构建固定的官方 SGLang 和对应的软件依赖。观察镜像在其上安装当前观察包，使用框架插件记录原生批次和语义调用。详细模式从原生 profiler 取得提交及设备证据，轻量模式从同一发布边界记录 token 数和时刻。观察目录由一次会话独占。`prologue compile <observation>` 在无设备的应用容器内编译可复用定义及其查询键，具体调用实例和观测时间保留在来源记录。局部父边界可以声明已有子定义的查询键和所需端口，由共同编译器保留实际连接。

`prologue verify-structure` 与 CPU 镜像 `prologue-scheduler:ubuntu22.04` 通过本地 Unix socket 建立一次仿真。原生循环负责接收、组批和结果处理，C++ 管理槽位、KV 页和虚拟时钟，并按实际动作从来源库展开。验证端持有独立目标记录。动作展开后才查询本动作所需的实测时长与边界时刻。验证入口核对实际工作、依赖、发布和资源效果。当前证据覆盖同步单卡 TP1，计时按每次调用内的 profiler 相对时间和主机 RAW 边界交接。

`fit-costs` 使用同一 C++ 坐标从详细来源提取设备工作，从轻量主机观测提取批准备、提交和结果服务。当前拟合在已观测联合坐标上取中位数。成本域包括模型、配置、框架提交、设备与驱动环境。声明物理域的 `predict` 根据原生动作查成本，`quote-costs` 和 `verify-performance` 共用查询。固定图保留本次实测输入就绪及结果边界，先回算原始端点，再替换设备服务。独立的 `score` 读取同输入的轻量记录。

`plan-costs` 从已绑定坐标合并可共采需求。Ascend 的定点观察命令在原生容器里用 SGLang 批次工具准备实际 KV，再采单成员 Decode attention。收据记录尝试、物理卡时和实际观察目录，重启沿同一任务保留计费。`fit-costs --for-queries` 允许仅回读缺失的成本坐标。追加成本保留现有模板与已覆盖坐标，原查询覆盖后才更新发布。

`publish` 校验模板、性能和规则的交接后，写入本地共享库。每份发布保存三个不可变资产引用。写者用预期基线保护当前指向，只在资产齐全后原子切换。读者先固定发布，再装配任务，预测和验证结果记录所用发布编号。`show-release` 可按编号查询。`query-structure` 和仿真使用同一套 C++ 选择与展开逻辑。按需追加模板时，用原查询复查候选及已有定义，再更新发布。原生观察模式按采集规则核对。

## 层次与构建边界

- `src/prologue/app/` 维护公开命令及对应的跨语言装配，`src/prologue/core/` 负责统一业务判定。任务级字段与 SGLang 配置分别在入口和框架适配侧解释。
- 主机用于编辑、Git 与容器调度。共同 C++ 目标在建模环境构建。设备采集桥随原生 SDK 单独构建和加载，正式纯预测只读取明确的输入与发布资产。
- 官方 SGLang 保留在 `third_party/sglang`。现有 Ascend 依赖层由 `docker/images/base/sglang` 构建。接入原生运行时记录实际提交、镜像 ID 和部署身份。模型、编译输出、采集数据与归档留在本地。
- 实验矩阵和请求来源组织留在 `example/`，可复用的单案例核验由正式验证模块维护。新的命令与镜像随各自的可用实现同步进入操作说明。
